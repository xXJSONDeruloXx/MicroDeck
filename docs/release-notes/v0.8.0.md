# MicroDeck v0.8.0: SteamOSXX is now MicroDeck

The project has a new name, as it grows past one handheld: **MicroDeck**, a Steam handheld OS for cheap ARM handhelds. This release is the
same system as v0.7.2 under the new name, plus two small fixes found while renaming. The repository is now
`xXJSONDeruloXx/MicroDeck`.

## What changed

- **Names.** The command is `mdeck` (it was `sxx`), helpers and services are `mdeck-*` (`mdeck-update`, `mdeck-sleep`, `mdeck-fit`, ...),
  settings variables are `MDECK_*`, images are `microdeck-rg40xx.img.xz` and `microdeck-rg28xx.img.xz`, and each handheld is named
  `microdeck-<device>` on the network (`ssh root@microdeck-rg28xx.local`) instead of both being `rg40xx`. A fresh card is labelled `MICRODECK`
  (the small partition you see on a PC), `microdeck-root` and `microdeck-data`; the kernel release is `7.2.0-mdeck`; the USB gadget says "MicroDeck".
- **Valve's own names are unchanged**: `steamos-update`, `steamos-session-select` and the other hooks Steam itself calls.
- **Cards from before the rename keep working** when flashed over: the installer and first-boot step accept the old partition labels,
  move the old state directory (`/home/.sxx`) to `/home/.mdeck`, and Steam games mapped to the old FEX tool name follow it to `mdeck-fex`.
  A wrapper name saved in a Steam launch option (`sxx-wrap`) still works through a small link.
- Checked on an RG28XX that had run v0.7.2 with its data kept: boots, Steam signs in, Geometry Wars (Proton) and Hotline Miami (FEX) run, the
  Steam menu opens over them, and a 40-second sleep wakes.

## Updating

**Update by flashing.** The update feed moved with the repository: installed v0.7.x updaters cannot see this release (GitHub answers their
old address with a redirect they do not follow), so write `microdeck-<device>.img.xz` to the card. The data partition (Steam, games, login)
is kept when you write over the same card. From this release on, Settings > System > Check For Updates works as before.

## Known issues

- Sleep is still opt-in (an empty file `sleep` on the `MICRODECK` partition, or `mdeck-sleep on`); waking by the power button has not been
  confirmed, and after a wake on an RG28XX the USB network may need a second gadget restart (seen once).
- Booting the RG28XX straight from slot 1 with no muOS has not been tried.
- Only the RG28XX has run this renamed build on hardware so far; the RG40XX-H image passes the same automated checks (boot test in the
  virtual device, unit tests) but has not been started on a real RG40XX-H since the rename.
