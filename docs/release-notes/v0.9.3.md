# MicroDeck v0.9.3: sleep started by Steam wakes properly, steadier scaler

## What's new

- **A sleep that Steam starts (its idle timer, Power > Sleep) now wakes cleanly.** Steam shows a full-screen "going to sleep" video, freezes the
  running game and waits for its client to report the resume before it closes the video and thaws the game. Nothing sent that report here, so
  a handheld that Steam put to sleep woke up and stayed on the animation (an RG28XX did, found overnight), and a running game would have stayed
  frozen. The sleep hook now tells Steam's UI the system resumed (the same call Steam's own report makes), and the animation closes about two
  seconds after the wake. A press of the power button (logind starts that sleep, Steam is not involved) was never affected.
- **Fixes found by an independent code review of the game scaler and the focus daemon:** the scaler no longer shows a black screen when the
  game opens a second window while it is running, a failed scaler start no longer leaves the overlay window over the screen, a scaler that
  died is started again, the focus daemon's periodic work can no longer be starved by busy windows, the web helper's one-core pin is released
  when the daemon ends, and a finished scaler leaves no zombie process.
- The focus daemon's log line "mdeck-fit reset failed" is gone (it was always printed, because of how child processes were waited for).

## Updating

Settings > System > Check For Updates, Apply, Restart.

## Known issues

- Mouse and touch input is not mapped through the scaling; pad-driven games are not affected.
- Games still take 25-140 s to start (Steam runs its install-script step, and with it Wine and the container, twice before each launch).
