# MicroDeck v0.9.4: Direct3D 11 games start, desktop mode is easier to find

## What's new

- **Direct3D 11 games start instead of failing with "error initializing player".** The session runs Proton on the GPU's Direct3D 9 path, which cannot create a
  Direct3D 11 device, so most Unity games (and anything else that needs Direct3D 11) stopped at an error. MicroDeck now detects Direct3D 11 games and
  switches them to DXVK (Vulkan on the CPU renderer) in their launch options, once; a game with launch options of its own is left alone. Vampire
  Survivors and 8-Bit Bayonetta now create their Direct3D 11 device and start. **They are slow**: this is software rendering on four small cores, so expect a
  long load and a low frame rate. Playable speed needs a Vulkan driver for the Mali GPU, which does not exist yet.
- **Unity's launcher dialog is skipped.** Windows Unity games open a "Configuration" dialog (resolution, quality, Play!) that a pad cannot click. Enter is
  now pressed on it once, with the defaults.
- **Desktop mode is easier to find.** The panel has an **Apps** button and app icons (browser, documents, spreadsheets, editor, files, terminal), a button labelled
  **Gaming mode** to go back to Steam, and a hint that **Start** opens the app menu; a click on the empty desktop opens the menu too. (A tester switched to the desktop,
  saw only a "Steam" button and thought it was broken.)
- The game scaler no longer shows black for windows that do not repaint by themselves (such as that dialog).

## Updating

Settings > System > Check For Updates, Apply, Restart.

## Known issues

- Direct3D 11 games are very slow (see above); Direct3D 9 games still use the faster GPU path.
- Mouse and touch input is not mapped through the scaling; pad-driven games are not affected.
- Games still take 25-140 s to start.
