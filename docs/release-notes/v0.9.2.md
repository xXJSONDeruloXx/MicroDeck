# MicroDeck v0.9.2: faster game launches

## What's new

- **Games start sooner.** While a game launches or runs, Steam's UI process (its web helper) is kept to one core instead of taking
  150-240 % CPU of the four that the container setup and Wine need. Launches measured 10-20 s faster (Eets reaches the front in 25 s instead of
  31-35 s). Steam's menu gets every core back while it is open. `MDECK_UI_PIN=0` in the environment of `mdeck-focus` turns it off.
- **Steam's notification toasts** (achievements, the volume pop-up) now show over a game that is being scaled, and the in-game menu appears the
  moment Steam asks for it.
- The scaler waits out the short-lived dialogs Wine opens while a game starts before it starts, so it no longer burns CPU on them.
- `GAME_ENV="NAME=value ..."` in `/etc/steam-session.conf` exports environment variables to Steam and every game it starts (for FEX settings
  and the like).

## Updating

Settings > System > Check For Updates, Apply, Restart.

## Known issues

- Games still take 25-140 s to start: Steam runs its install-script step (Wine and the container twice) before each launch of a game that lists the
  shared redistributables, and a way to skip it safely has not been found.
- Mouse and touch input is not mapped through the scaling; pad-driven games are not affected.
- Sleep is on by default: a plugged-in handheld that sits idle may sleep (Steam's Settings > Power sets when), and a short press of the power button wakes it.
